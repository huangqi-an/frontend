事件循环是 JavaScript 实现异步非阻塞 I/O 的核心机制，浏览器和 Node.js 都基于 V8 引擎，但由于运行环境不同，它们的事件循环机制在实现细节上有所区别。
浏览器的事件循环由调用栈、宏任务队列、微任务队列组成。从全局脚本开始，所有同步代码进入调用栈执行。遇到异步任务时，交由浏览器API。异步任务完成后，会将回调函数放入任务队列中。任务队列分为宏任务队列和微任务队列，宏任务包括：setTimeout、setInterval、setImmediate（Node.js）、I/O操作、UI渲染，微任务包括：Promise().then()/.catch()/.finally()、MutationObserver、process.nextTick（Node。js）。
事件循环每一轮都会重复进行，清空执行栈的同步代码，然后检查微任务队列，清空微任务，在这个过程中产生的微任务会追加到微任务队列末尾。然后检查是否需要UI渲染。然后从宏任务队列中取出一个任务执行，如此循环往复

在nodejs中，事件循环基于libuv实现，分为六个阶段：
1.timer（定时器阶段），执行 setTimeout 和 setInterval 的回调。
2.Pending（待定回调阶段），执行 I/O 回调（如文件系统、网络错误等）。
3.Idle，Prepare（空闲/准备阶段），内部使用。
4.Poll（轮询阶段），获取新的I/O事件，Node可能在此阻塞。
5.Check（检查阶段），执行setImmediate的回调。
6.Close Callbacks（关闭回调阶段），执行关闭请求的回调，如 socket.on('close', ...)。

关键点（Node.js 版本差异）：
在 Node.js 11 之前，微任务是在各个阶段之间执行的，行为比较复杂。
在 Node.js 11 及之后，为了与浏览器行为保持一致，其行为发生了变化：每个阶段执行完毕后，都会像浏览器一样，清空微任务队列。
此外，Node.js 中还有一个特殊的微任务 process.nextTick，它的优先级高于其他微任务（如 Promise），会在当前操作结束后、进入下一个事件循环阶段前立即执行。
